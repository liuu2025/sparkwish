# sparkwish 祝福语小程序

当前源码版本：**v1.0.3**。更新内容见[版本记录](CHANGELOG.md)。页面版本继续读取微信运行时信息，上传微信时使用对应版本号。

原生微信小程序。免费祝福语在本地生成，不登录、不联网；套餐页已接入中枢目录、小程序虚拟支付与订单查询。

## 已实现

- 六个首批场景：生日、节日通用、婚礼、升学、乔迁、感谢
- 填写称呼（选填）、关系、风格（温馨/正式/幽默/简洁）、长度（短句/适中/长文）
- 每次生成三条候选，支持复制、换一组、返回修改
- 结果文字可选择，长文自动换行
- 复制成功使用自动消失的轻提示，复制失败提示失败
- 返回填写页时保留当前输入
- 权益中心：读取中枢在售套餐，展示名称、价格与购买按钮；顶部提供我的订单与刷新
- 购买：下单 → 调起小程序虚拟支付 → 请中枢核对 → 订单详情展示卡密
- 我的订单：按小程序身份读取自己的订单，展示状态与卡密掩码
- 订单详情：状态、商品、祝福语与卡密分区，分别复制
- 首页与结果页提供套餐入口，免费流程不要求登录或购买
- 全页面采用纯色深紫主题与分层卡片阴影；可点击卡片保留按压反馈
- 手动刷新实时读取目录，刷新中保留当前套餐，失败保留旧列表并轻提示；成功返回空目录时同步更新本地缓存
- 进入权益中心时后台准备登录，商品展示不等待登录；选择套餐时并行准备并复用下单编号，确认后才创建订单
- 下单与准备支付的提示连续展示到调用微信收银台，正常已交付订单详情只保留“已交付”标题

## 高级商品与订单对接（交接说明）

消费者页面只展示商品名称、价格、购买按钮与订单状态；权益规则保留在中枢，不在小程序内展示。以下技术边界只记录在这里。

### 配置项（`miniprogram/config/shop.js`）

| 字段 | 用途 | 当前值 |
|---|---|---|
| `baseURL` | 中枢购买服务 HTTPS 地址 | `https://buy.douyinspark.top` |
| `projectID` | 商品所属平台项目标识 | `sparkpilot` |
| `planIDs` | 套餐展示顺序 | 月套餐、100 条永久额度 |
| `paymentMethod` | 渠道支付方式 | `virtual` |
| `ordersEnabled` | 订单查询接口是否接入 | `true` |
| `paymentEnabled` | 真实支付是否开放（开启即真实扣款） | `true` |
| `timeout` | 请求超时（毫秒） | 15000 |

- `baseURL` 必须是 HTTPS 且非 `example.com` 类占位值，否则不发请求。
- 前端不保存、不读取任何密钥；AppSecret、OfferID、AppKey 只在中枢后端配置。

### 未配置与未接入时的行为

| 页面 | 条件 | 表现 |
|---|---|---|
| 套餐页 | `baseURL` 或 `projectID` 为空 | 显示“商品信息暂未配置”，不发起请求 |
| 套餐页 | 已配置但目录为空 | 显示“当前暂无在售套餐” |
| 我的订单 / 订单详情 | `ordersEnabled=false` | 显示“订单服务暂未接入”，不显示“暂无订单” |
| 我的订单 / 订单详情 | 身份或网络异常 | 显示“暂时无法获取”，并保留重试入口 |
| 全部 | `paymentEnabled=false` | 购买按钮不可用，并说明“购买功能暂未开放”（当前为 `true`） |

### 对接结构

- `utils/shop.js` 封装：`catalog`、`mini/login`、`checkout-id`、`orders`、`orders/pay`、`orders/query`、`orders/sync`、`mini/orders`。
- 下单固定带 `payment_method=virtual`；进入权益中心后台准备登录，选择套餐与确认购买共用同一编号准备任务，不提前创建订单。
- 支付前通过 `wx.checkSession` 检查微信登录态，并复用尚未到期的中枢会话；检查失败、接口缺失或检查超时则重新登录。中枢返回401时最多重登并重试原请求一次，网络或存储错误不按身份过期处理。
- `wx.login` 集中在 `utils/shop.js`，令牌只存内存，期限从登录请求开始保守计算。`wx.checkSession` 检查最后一次获取code对应的登录态；后续新增登录或数据预拉取必须统一协调，不能在其他位置获取code后继续使用旧令牌签名。参见[微信官方API类型与说明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。
- `orders/query` 只读订单，`orders/sync` 请中枢核对支付；前端支付回调不作为到账依据。
- 会话令牌只存内存；私密查询号与卡密不写入本地缓存、页面路径、日志或错误提示。
- 下单只把 `projectID/planID/planVersion/checkoutID` 存入本地用于恢复原订单；结果未知时沿用原 `checkoutID`，不新建订单。
- 原下单信息读取、格式或保存异常会阻止提交新订单；迟到的准备结果不覆盖当前编号，成功结果只清理自己对应的恢复编号。
- 网络失败统一归为“结果未知”，保留原订单、仅重试查询，不判为失败或关闭。
- 订单状态取自中枢 `payment_status` / `delivery_status`，未知取值进入“状态待确认”分支：
  - `pending` + `not_started` → 待付款
  - `paid` + `pending` → 已付款，正在交付
  - `paid` + `delivered` → 已交付
  - `paid` + `confirmation_pending` → 已交付（微信侧发货确认处理中，卡密已可展示）
  - `closed` → 已关闭
- 订单详情用小程序身份读取自己的订单；公开订单号不构成查询凭证。

### 已知限制

- 所售套餐属于中枢项目 `sparkpilot`，名称与价格由目录决定；权益规则只在中枢维护，小程序不展示也不承诺。
- 高级祝福语仍是本地模板生成，可被提取；付费与否不影响文本能否被本地获取。
- 祝福语原文不持久化，订单只恢复订单与卡密，跨设备不承诺恢复同一段文字。
- 未提供卡密兑换截止时间字段，页面暂不展示该行，也不推测。
- 未做卡密输入解锁、卡密核销或“已购买即永久解锁”。

## 当前边界

- 免费流程不登录、不下单、不支付、不发卡密，也不触发网络请求。
- 权益中心会并行读取公开目录与准备小程序身份；我的订单、订单详情会用小程序身份读取自己的订单。我的订单列表继续只显示中枢已确认付款的订单。
- 支付已开启：下单、调起小程序虚拟支付、支付后请中枢核对；前端不判定付款成功，一切以中枢返回为准。
- 不生成、不预置卡密，不根据支付回调自行发卡。
- 所有免费生成在本地完成，不使用 AI，不上传填写内容。
- 未在微信开发者工具中编译验证的部分标注为待验证。
